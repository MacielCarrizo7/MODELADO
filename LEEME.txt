CÓMO INSTALARLO (con XAMPP)

1. Copiá toda esta carpeta "stock_app" dentro de htdocs
   (ej: C:\xampp\htdocs\stock_app)

2. Abrí phpMyAdmin (http://localhost/phpmyadmin)
   - Andá a la pestaña "SQL"
   - Pegá todo el contenido de database.sql y ejecutalo
   (esto crea la base "control_stock" con las tablas usuarios, productos y ventas)

3. Prendé Apache y MySQL desde el panel de XAMPP

4. Instalá las dependencias desde una consola, dentro de stock_app:
   composer install --no-dev --optimize-autoloader

5. Configurá una clave externa para cifrar los secretos TOTP.
   Generá una clave una sola vez (el resultado es privado):
   C:\xampp\php\php.exe -r "echo base64_encode(random_bytes(32)), PHP_EOL;"

   Guardala como variable de entorno CONTROL_STOCK_TOTP_KEY y reiniciá Apache.
   En Apache también puede definirse dentro del VirtualHost:
   SetEnv CONTROL_STOCK_TOTP_KEY "VALOR_BASE64_GENERADO"

   IMPORTANTE: no cambies ni pierdas esta clave mientras haya usuarios con 2FA
   activo. No la guardes en este proyecto, Git, registros ni copias públicas.

6. Entrá a: http://localhost/stock_app/login.php
   - El acceso solicita DNI, nombre, apellido y contraseña.
   - Después solicita el código TOTP de una aplicación autenticadora.
   - En el primer acceso válido se muestra un QR para activar el segundo factor.
   - Solo un administrador puede crear cuentas desde la sección "Usuarios".

FLUJO DEL SISTEMA
- login.php: acceso público (sin registro de cuentas)
- configurar_totp.php: enrolamiento protegido por el primer factor
- verificar_totp.php: validación TOTP antes de crear la sesión autenticada
- registro.php: gestión de usuarios protegida, exclusiva para administradores
- admin.php / vendedor.php / cliente.php: paneles separados por rol
- stock.php: redirección segura al panel correspondiente
- LISTA DE PRODUCTOS: cargás productos con nombre, precio y stock
- VENTAS: elegís un producto y una cantidad; el sistema calcula el total,
  descuenta el stock automáticamente y guarda quién hizo la venta

Si conexion.php no conecta, revisá que $usuario y $clave coincidan con
tu configuración de MySQL (por defecto en XAMPP es root sin contraseña).

SISTEMA DE ROLES (3 NIVELES)
Si ya tenías la base creada, corré en phpMyAdmin el archivo agregar_roles.sql
(solo agrega la columna "rol" a la tabla usuarios, no borra nada).

Para agregar apellidos a una instalación anterior, corré una sola vez
migracion_apellido_usuarios.sql. Conserva todas las cuentas y datos existentes.
Las cuentas anteriores completan su apellido en el primer acceso válido.

Para habilitar clientes, estados y auditoría en ventas, corré una sola vez
migracion_trazabilidad_ventas.sql. Las ventas anteriores se conservan como
ACTIVA y sin cliente, porque el sistema anterior no guardaba esa relación.

Para agregar 2FA a una instalación existente, corré una sola vez
migracion_totp_usuarios.sql. Conserva todos los usuarios; cada uno configura
su aplicación TOTP después de validar sus credenciales habituales.

SEGURIDAD DEL SEGUNDO FACTOR
- Implementación TOTP local compatible con aplicaciones estándar; no usa Firebase.
- Secreto cifrado en MariaDB con AES-256-GCM y clave externa al repositorio.
- QR visible únicamente durante el enrolamiento posterior al primer factor.
- Ventana de reloj aceptada: código anterior, actual o siguiente (±30 segundos).
- Un código aceptado no puede reutilizarse, ni siquiera en otra sesión.
- Tras 5 intentos fallidos, la verificación se bloquea durante 60 segundos.
- El paso pendiente vence a los 10 minutos.
- Ningún panel o endpoint acepta una sesión sin mfa_verified.
- El administrador puede restablecer 2FA, pero nunca ver el secreto del usuario.
- No hay códigos de recuperación: si se pierde el dispositivo, un administrador
  debe restablecer 2FA desde Gestión de usuarios.

- admin: agrega/elimina productos, carga ventas, ve historial completo
- vendedor: carga ventas para un cliente, filtra y gestiona el historial
- cliente: ve productos y gestiona únicamente sus compras asociadas

El rol se asigna únicamente desde el panel de un administrador.
